# 05-Sentinel熔断限流降级

## 1. 面试先给结论

Sentinel 是流量治理组件，核心能力是限流、熔断、降级和系统保护。

它解决的问题不是让系统无限承载流量，而是在流量突增、下游变慢、错误率升高时，保护核心链路不被拖垮。

面试表达可以这样说：

> Sentinel 主要用于微服务流量治理。它可以对接口、方法、服务调用等资源设置限流规则，也可以根据慢调用比例、异常比例、异常数进行熔断。我的理解是，限流是防止入口流量过大，熔断是防止下游故障扩散，降级是在非核心能力不可用时返回兜底结果，核心目标是保护系统稳定性。

## 2. 为什么需要 Sentinel

微服务系统常见风险：

- 某个接口突然被大量访问。
- 下游服务变慢。
- 数据库慢 SQL 增多。
- 第三方接口不可用。
- 重试导致流量放大。
- 非核心功能拖垮核心链路。

如果没有流量治理，一个服务慢可能拖垮多个上游。

Sentinel 可以做：

- 限流。
- 熔断。
- 降级。
- 热点参数限流。
- 系统自适应保护。
- 规则动态调整。

## 3. 核心概念：资源

Sentinel 保护的对象叫资源。

资源可以是：

- 一个接口。
- 一个方法。
- 一个 Feign 调用。
- 一个业务动作。
- 一个消息消费逻辑。

例如：

```text
/api/query/score
queryScoreByTicketNo
syncConsumerHandler
user-service#getUser
```

只要定义为资源，就可以配置限流或熔断规则。

## 4. 限流

### 4.1 限流解决什么

限流解决的是流量超过系统承载能力的问题。

比如中考查询系统：

```text
成绩开放查询后，10 分钟内大量考生集中访问。
如果请求全部打到应用和数据库，系统可能被压垮。
```

限流目标：

- 控制进入系统的请求量。
- 保护线程池、连接池、数据库。
- 保证核心请求有机会被处理。

### 4.2 常见限流维度

- 按接口限流。
- 按用户限流。
- 按 IP 限流。
- 按租户限流。
- 按热点参数限流。

Sentinel 常见是按资源 QPS 或并发线程数限流。

### 4.3 QPS 限流和线程数限流

QPS 限流：

- 控制每秒请求数量。
- 适合入口流量控制。

线程数限流：

- 控制同时处理的并发数。
- 适合保护慢接口和资源池。

面试表达：

> QPS 限流控制单位时间进入资源的请求数量，线程数限流控制同时执行该资源的并发数。如果接口很快，QPS 限流更直观；如果接口耗时不稳定，线程数限流能更直接保护线程资源。

## 5. 热点参数限流

热点参数限流适合某些参数被集中访问的场景。

例如：

- 某个学校成绩被大量查询。
- 某个商品被秒杀。
- 某个租户突然请求量很高。
- 某个业务主键同步失败被频繁重推。

普通接口限流只能限制整个接口。

热点参数限流可以限制某个参数值：

```text
/api/query/score?schoolId=1001
```

如果 `schoolId=1001` 访问过高，可以单独限制它，避免影响其他学校。

## 6. 熔断

### 6.1 熔断解决什么

熔断解决的是下游服务异常或变慢导致故障扩散的问题。

比如：

```text
查询服务 -> 成绩数据服务 -> 数据库
```

如果成绩数据服务变慢，查询服务一直等待，就可能导致查询服务线程池被占满。

熔断后，查询服务短时间内不再调用下游，直接走降级逻辑。

### 6.2 Sentinel 常见熔断策略

慢调用比例：

- 请求耗时超过阈值，认为是慢调用。
- 慢调用比例超过阈值后熔断。

异常比例：

- 异常请求占比过高时熔断。

异常数：

- 单位时间异常数量超过阈值时熔断。

面试表达：

> 慢调用比例适合下游变慢但不一定报错的场景；异常比例适合错误率升高的场景；异常数适合低 QPS 接口，因为低流量下比例可能不稳定。

## 7. 降级

降级是在资源不可用时提供兜底方案。

常见降级方式：

- 返回默认值。
- 返回缓存数据。
- 返回“系统繁忙，请稍后再试”。
- 写入异步任务。
- 进入补偿流程。
- 关闭非核心功能。

注意：

> 降级不是吞掉错误，而是有意识地牺牲非核心能力，保护核心链路。

## 8. 限流、熔断、降级的区别

限流：

- 面向入口流量。
- 防止请求量超过系统承载能力。
- 关键词：流量太大。

熔断：

- 面向下游依赖。
- 防止下游故障拖垮上游。
- 关键词：下游慢或错误率高。

降级：

- 面向业务兜底。
- 牺牲非核心能力保证核心可用。
- 关键词：兜底返回或补偿。

面试表达：

> 限流是入口保护，熔断是依赖保护，降级是业务兜底。三者经常一起使用，比如接口流量过大先限流，下游慢调用比例过高则熔断，熔断后走降级返回缓存或提示。

## 9. Sentinel 和 Gateway 的关系

Gateway 可以做入口限流。

Sentinel 可以做更细粒度的应用保护。

组合方式：

```text
Nginx -> Gateway 限流 -> 应用 Sentinel 限流/熔断 -> 下游服务
```

Gateway 更适合：

- 入口流量控制。
- IP、路径、用户维度限流。
- 统一鉴权前置保护。

Sentinel 更适合：

- 具体方法保护。
- Feign 调用保护。
- 热点参数限流。
- 慢调用熔断。
- 业务降级。

## 10. Sentinel 和 Feign 的关系

Feign 是远程调用组件。

Sentinel 可以保护 Feign 调用。

比如：

```text
query-service -> score-data-service
```

如果 `score-data-service` 慢调用比例升高，Sentinel 可以对这个 Feign 资源熔断，让查询服务走降级。

降级方式：

- 返回缓存数据。
- 返回查询处理中。
- 提示稍后再试。
- 写入异步任务。

## 11. 项目一：中考查询系统怎么用 Sentinel

中考查询系统是 Sentinel 很好的项目表达场景。

可以保护的资源：

- 成绩查询接口。
- 准考证号查询方法。
- 学校维度查询方法。
- 数据库查询方法。
- 通知接口。

可设计规则：

- 查询接口 QPS 限流。
- 单个 IP 限流。
- 准考证号热点参数限流。
- 数据库查询线程数限流。
- 成绩数据服务慢调用熔断。
- 非核心通知功能降级。

面试表达：

> 中考查询系统中，Sentinel 主要用于保护查询主链路。入口层可以按查询接口 QPS 限流，应用层可以对准考证号或学校 ID 做热点参数限流，防止某些参数被频繁刷。同时对数据库查询方法设置线程数限流，避免慢查询把线程池打满。非核心通知或统计接口可以降级，优先保证成绩查询可用。

## 12. 项目二：数据同步平台怎么用 Sentinel

数据同步平台也可以使用 Sentinel，但重点不是用户入口，而是保护下游依赖和补偿接口。

可保护资源：

- 人工补偿接口。
- 批量重推接口。
- 源库查询方法。
- 目标库写入方法。
- 下游系统接口。
- 消费处理方法。

可设计规则：

- 补偿接口限流。
- 批量重推限流。
- 下游服务慢调用熔断。
- 目标库写入线程数限制。
- 消费失败进入失败表或 DLQ。

面试表达：

> 数据同步平台中，我不会让补偿任务无限制地重推失败数据。可以对人工补偿接口和批量重推接口做限流，防止瞬间大量请求打到 Kafka 或数据库。同时对下游接口或目标库写入设置熔断和线程数保护，如果下游持续异常，就暂停重试或进入失败表，避免故障扩大。

## 13. 常见生产问题

### 13.1 限流阈值怎么设置

思路：

- 参考压测结果。
- 参考数据库连接池能力。
- 参考接口 RT。
- 参考服务器 CPU、内存。
- 先保守设置，再观察调整。

不能拍脑袋设置。

面试表达：

> 限流阈值最好来自压测和线上监控。比如接口稳定承载 2000 QPS，数据库和 Redis 指标正常，可以把阈值设在略低于极限的位置，并保留一定水位。后续根据监控动态调整。

### 13.2 被限流后怎么返回

常见方式：

- 返回 429。
- 返回系统繁忙。
- 返回排队中。
- 返回缓存结果。
- 前端稍后重试。

注意：

- 不要返回复杂堆栈。
- 不要让前端无限重试。
- 核心接口要有用户可理解的提示。

### 13.3 熔断后什么时候恢复

熔断通常有三个状态：

- Closed：正常调用。
- Open：熔断打开，直接降级。
- Half-Open：半开，尝试少量请求。

如果半开请求成功，恢复正常。

如果半开请求失败，继续熔断。

## 14. 高频问题

### 14.1 Sentinel 的作用是什么

答法：

> Sentinel 是流量治理组件，主要做限流、熔断、降级和系统保护，用来防止流量突增或下游故障拖垮系统。

### 14.2 限流和熔断有什么区别

答法：

> 限流是控制入口请求量，防止流量超过系统承载能力；熔断是下游依赖慢或异常时，暂时停止调用，防止故障扩散。

### 14.3 熔断和降级有什么区别

答法：

> 熔断是判断是否继续调用下游的保护机制，降级是熔断或异常后返回什么兜底结果。熔断偏策略，降级偏业务返回。

### 14.4 Sentinel 如何保护 Feign 调用

答法：

> 可以把 Feign 调用作为资源，当下游慢调用比例、异常比例或异常数达到阈值时触发熔断，然后走 fallback 降级逻辑，避免上游线程长期阻塞。

### 14.5 数据同步平台为什么也需要限流

答法：

> 因为补偿重推、人工批量处理、下游写入都可能形成瞬时压力。如果不限制，失败数据集中重推可能压垮 Kafka、数据库或目标系统。所以需要对补偿接口、批量任务和下游调用做限流和熔断。
