# 04-OpenFeign远程调用与超时重试

## 1. 面试先给结论

OpenFeign 是 Spring Cloud 中声明式 HTTP 调用组件，用接口的方式调用远程服务，底层仍然是 HTTP 请求。

它解决的是微服务之间同步调用的开发便利性问题，但真正的重点是超时、重试、熔断、降级和异常边界。

面试表达可以这样说：

> OpenFeign 让我们像调用本地接口一样调用远程服务，但它本质上还是网络调用，不能真的当成本地方法。使用 Feign 时必须设置超时时间、控制重试次数，并结合 Sentinel 或 Resilience4j 做熔断降级，否则下游服务慢或者不可用时，容易把上游线程池拖垮。

## 2. 为什么需要 OpenFeign

服务拆分后，经常需要同步调用其他服务。

如果直接用 HTTP 工具调用：

```java
String url = "http://user-service/user/" + userId;
UserDTO user = restTemplate.getForObject(url, UserDTO.class);
```

问题：

- URL 拼接分散。
- 参数和返回值不直观。
- 错误处理重复。
- 代码不够清晰。

OpenFeign 使用接口声明远程调用：

```java
@FeignClient(name = "user-service")
public interface UserClient {

    @GetMapping("/users/{id}")
    UserDTO getById(@PathVariable("id") Long id);
}
```

业务代码：

```java
UserDTO user = userClient.getById(userId);
```

价值：

- 声明式调用。
- 与注册中心集成。
- 支持负载均衡。
- 支持拦截器。
- 支持超时配置。
- 可结合熔断降级。

## 3. OpenFeign 调用流程

典型流程：

```text
1. 业务代码调用 Feign 接口。
2. Feign 根据注解生成 HTTP 请求。
3. 根据服务名从注册中心获取实例列表。
4. 负载均衡选择一个实例。
5. 发起 HTTP 请求。
6. 解析响应结果。
7. 返回给业务代码。
```

注意：

> Feign 看起来像本地调用，但它存在网络延迟、超时、失败、重试、序列化成本。

## 4. Feign 和 RestTemplate 的区别

RestTemplate：

- 编程式 HTTP 调用。
- 手动拼接 URL。
- 调用逻辑更直接。
- 代码容易分散。

OpenFeign：

- 声明式 HTTP 调用。
- 接口化表达远程服务。
- 与注册中心、负载均衡、熔断更容易集成。
- 更适合微服务内部调用。

面试表达：

> RestTemplate 更像通用 HTTP 客户端，Feign 更像微服务调用客户端。Feign 通过接口声明远程服务，代码更清晰，也更容易统一配置超时、日志、拦截器和降级。

## 5. 超时为什么重要

远程调用最怕没有超时。

如果下游服务卡住，上游线程会一直等待，可能导致：

- Tomcat 线程被占满。
- Feign 调用线程阻塞。
- 连接池耗尽。
- 请求堆积。
- 上游服务也被拖垮。

所以远程调用必须设置：

- 连接超时。
- 读取超时。

示例：

```yaml
spring:
  cloud:
    openfeign:
      client:
        config:
          default:
            connectTimeout: 1000
            readTimeout: 3000
```

含义：

- `connectTimeout`：建立连接的最长等待时间。
- `readTimeout`：连接建立后等待响应的最长时间。

## 6. 重试要谨慎

重试不是越多越好。

重试适合：

- 网络短暂抖动。
- 下游瞬时超时。
- 临时连接失败。
- 幂等接口。

重试不适合：

- 非幂等写操作。
- 下游已经明显故障。
- 慢 SQL 导致的整体超时。
- 高峰期系统已经过载。

重试风险：

- 放大流量。
- 加重下游压力。
- 造成重复写入。
- 拉长上游响应时间。

面试表达：

> 我不会对所有 Feign 调用无脑重试。读接口或者幂等接口可以设置有限重试；写接口要非常谨慎，必须有幂等键。下游已经过载时，重试可能会把故障放大，这时应该熔断或降级。

## 7. 超时、重试、熔断、降级的关系

### 7.1 超时

超时是单次调用的最大等待时间。

解决问题：

- 不让线程无限等待。

### 7.2 重试

重试是在失败后再次尝试。

解决问题：

- 短暂抖动。

风险：

- 放大流量。
- 重复调用。

### 7.3 熔断

熔断是在失败率或慢调用比例过高时，短时间内不再调用下游。

解决问题：

- 防止故障扩散。

### 7.4 降级

降级是下游不可用时返回兜底结果或走异步补偿。

解决问题：

- 保证核心链路可用。

一条合理链路：

```text
设置超时 -> 有限重试 -> 熔断保护 -> 降级兜底
```

## 8. Feign 调用的幂等问题

远程写接口如果重试，可能造成重复写入。

比如：

```text
创建订单接口超时 -> 上游重试 -> 下游可能创建两次订单
```

解决方式：

- 业务唯一键。
- 幂等请求号。
- 防重表。
- 状态机判断。
- 数据库唯一索引。

面试表达：

> 对于写接口，我会要求调用方传业务唯一请求号，下游基于唯一键做幂等。否则 Feign 超时后，上游不知道下游是否已经执行成功，贸然重试可能导致重复写入。

## 9. Feign 日志

Feign 支持打印请求日志。

常见级别：

- NONE：不记录。
- BASIC：记录请求方法、URL、状态码、耗时。
- HEADERS：额外记录 Header。
- FULL：记录 Header、Body、元数据。

生产建议：

- 默认不要开 FULL。
- 排查问题时临时打开。
- 注意敏感信息脱敏。
- 大报文接口要谨慎。

## 10. 项目一：中考查询系统中的 Feign

假设中考查询系统拆分为：

- 查询服务。
- 成绩数据服务。
- 用户认证服务。
- 通知服务。

查询服务可能调用成绩数据服务。

设计要点：

- 查询接口设置较短超时。
- 查询结果优先走 Redis 缓存。
- 下游慢时返回“查询处理中”或稍后重试。
- 非核心通知调用异步化。
- 不在查询主链路中串行调用多个慢服务。

面试表达：

> 中考查询系统的高峰查询链路，我会尽量减少同步 Feign 调用，优先使用缓存和本地数据。如果必须调用成绩数据服务，会设置较短超时，并配合降级策略，避免下游慢导致查询入口线程被打满。

## 11. 项目二：数据同步平台中的 Feign

数据同步平台中，Feign 适合用于管理后台和内部服务协作，不适合替代 Kafka 主同步链路。

适合 Feign 的场景：

- 管理后台查询同步状态。
- 调用补偿服务触发重推。
- 查询某条失败记录详情。
- 调用权限服务校验用户身份。

不适合 Feign 的场景：

- 大批量数据同步主链路。
- 需要削峰的同步任务。
- 下游不稳定的批量写入。

面试表达：

> 数据同步主链路我会使用 Kafka，而不是 Feign，因为同步链路需要异步解耦、削峰和补偿。Feign 更适合管理后台这类需要实时返回结果的内部调用，比如失败记录查询、补偿任务触发、权限校验等。

## 12. 常见生产问题

### 12.1 Feign 超时频繁

排查方向：

- 下游接口 RT 是否升高。
- 数据库是否慢 SQL。
- 下游线程池是否打满。
- 网络是否抖动。
- Feign 超时时间是否太短。
- 是否存在大报文传输。

### 12.2 Feign 调用放大故障

现象：

- 下游服务变慢。
- 上游不断重试。
- 下游压力更大。
- 最后多个服务一起超时。

处理：

- 限制重试。
- 开启熔断。
- 核心接口降级。
- 慢接口异步化。
- 增加监控告警。

### 12.3 Feign 返回 404 或找不到服务

排查方向：

- 服务名是否正确。
- Nacos 是否注册成功。
- 路径是否匹配。
- 服务是否健康。
- namespace/group 是否一致。

## 13. 高频问题

### 13.1 Feign 的作用是什么

答法：

> Feign 是声明式 HTTP 客户端，用接口的方式调用远程服务。它可以结合注册中心和负载均衡，通过服务名调用目标服务。

### 13.2 Feign 是本地调用吗

答法：

> 不是。它只是写法像本地接口，本质是远程 HTTP 调用，有网络延迟、超时、失败、序列化和重试问题。

### 13.3 Feign 超时和重试怎么设置

答法：

> 要设置连接超时和读取超时。重试要谨慎，只适合幂等接口和短暂网络抖动。写接口如果重试，必须有业务唯一键或幂等机制。

### 13.4 下游服务慢了怎么办

答法：

> 先设置合理超时，避免线程长时间阻塞；再看是否允许有限重试；如果失败率或慢调用比例高，要熔断；非核心功能可以降级或异步补偿。

### 13.5 为什么数据同步不用 Feign 直接调

答法：

> 数据同步链路需要异步解耦、削峰、失败重试和补偿。Feign 是同步调用，下游慢会阻塞上游线程，也不适合承载大批量同步，所以主链路更适合 Kafka，管理类实时操作可以用 Feign。
