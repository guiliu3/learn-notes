1. 可重入锁：多线程同步机制，允许同一个线程多次获取锁。而不会导致死锁。比如常见的synchronized和ReentrantLock都是可重入锁。

2. 重入操作：一般是先要记录下来当前锁是归属于哪个线程的，然后再记录当前锁被重入了多少次。这样在加锁的时候判断是不是当前线程持有的锁，如果是则重入次数+1，否则重入失败。

3. 解锁操作：在解锁时也同理，锁是当前线程加的，那就重入次数-1，直到等于0的时候，直接解锁。


- 重点看在ReentrantLock的获取锁和释放锁的逻辑就知道了重入锁的机制

```java
 if (current == getExclusiveOwnerThread()) {
        int nextc = c + acquires;
        if (nextc < 0)
        throw new Error("Maximum lock count exceeded");
        setState(nextc);
        return true;

 ```
- 首先会判断是否是当前线程，若只有锁的线程和当前线程一致。则次数+1.


```java
protected final boolean tryRelease(int releases) {
    int c = getState() - releases;
    if (Thread.currentThread() != getExclusiveOwnerThread())
        throw new IllegalMonitorStateException();
    boolean free = false;
    if (c == 0) {
        free = true;
        setExclusiveOwnerThread(null);
    }
    setState(c);
    return free;
}

```
- 若当前线程和持有锁的线程不是同一个线程，直接解锁失败
- 若次数为0则直接释放锁成功。否则次数-1
