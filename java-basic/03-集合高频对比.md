# 03-集合高频对比

## 1. ArrayList 和 LinkedList

### 1.1 底层结构

`ArrayList`：

- 底层是动态数组。
- 支持随机访问。
- 扩容需要数组复制。

`LinkedList`：

- 底层是双向链表。
- 插入删除节点本身快。
- 随机访问慢，需要遍历。

### 1.2 查询和插入性能

`ArrayList`：

- 按下标查询：O(1)。
- 尾部追加：均摊 O(1)。
- 中间插入删除：O(n)，因为要移动元素。

`LinkedList`：

- 按下标查询：O(n)。
- 已知节点插入删除：O(1)。
- 按位置插入删除：仍然 O(n)，因为要先找到位置。

面试重点：

> 不要简单说 LinkedList 插入删除一定比 ArrayList 快。如果需要先按下标查找位置，LinkedList 也要遍历，未必更快。

## 2. ArrayList 扩容机制

默认无参构造时，底层数组初始为空。

第一次添加元素时扩容到 10。

之后扩容为原来的 1.5 倍左右。

面试表达：

> ArrayList 底层是数组，添加元素时如果容量不够，会扩容为原来的 1.5 倍左右，并把旧数组复制到新数组。所以如果能预估容量，最好指定初始容量，减少扩容和复制成本。

## 3. HashSet 和 HashMap

`HashSet` 底层基于 `HashMap`。

`HashSet` 的元素作为 HashMap 的 key，value 是一个固定占位对象。

所以：

- HashSet 去重依赖 hashCode 和 equals。
- HashSet 无序。
- HashSet 允许一个 null。

面试表达：

> HashSet 底层就是 HashMap，Set 的元素放在 HashMap 的 key 上，value 是固定对象。所以 HashSet 判断重复，本质还是依赖 key 的 hashCode 和 equals。

## 4. HashMap 和 Hashtable

`HashMap`：

- 线程不安全。
- 允许 null key 和 null value。
- 性能较好。

`Hashtable`：

- 线程安全，但方法级 synchronized。
- 不允许 null key 和 null value。
- 锁粒度大，性能差。
- 较老，不推荐新代码使用。

多线程场景优先用：

```text
ConcurrentHashMap
```

## 5. HashMap 和 TreeMap

`HashMap`：

- 基于哈希表。
- 查询平均 O(1)。
- 不保证顺序。

`TreeMap`：

- 基于红黑树。
- 查询、插入、删除 O(log n)。
- key 有序。
- 支持范围查询。

适用：

- 只需要快速查找：HashMap。
- 需要 key 排序或范围查询：TreeMap。

## 6. fail-fast 和 fail-safe

### 6.1 fail-fast

典型集合：

- ArrayList。
- HashMap。

遍历时如果集合被结构性修改，可能抛：

```text
ConcurrentModificationException
```

原理：

- modCount。
- expectedModCount。

注意：

> fail-fast 只是尽力检测并发修改，不是线程安全机制。

### 6.2 fail-safe

典型集合：

- CopyOnWriteArrayList。
- ConcurrentHashMap 的弱一致迭代器。

遍历时不一定抛异常。

## 7. CopyOnWriteArrayList

底层思想：

```text
读不加锁
写时复制新数组
写完替换引用
```

适合：

- 读多写少。
- 集合不大。
- 对实时一致性要求不高。

不适合：

- 写频繁。
- 数据量大。

面试表达：

> CopyOnWriteArrayList 适合读多写少场景。写操作会复制整个数组，成本较高，所以不适合频繁写和大集合。

## 8. 高频问题

### 8.1 ArrayList 和 LinkedList 区别

答法：

> ArrayList 底层是数组，随机访问快，尾部追加快，但中间插入删除要移动元素。LinkedList 底层是双向链表，按下标访问慢，已知节点插入删除快。但如果要先查找位置，LinkedList 也不一定快。

### 8.2 HashSet 如何去重

答法：

> HashSet 底层基于 HashMap，元素作为 key。去重依赖 hashCode 和 equals，hashCode 定位桶，equals 判断是否同一个元素。

### 8.3 ArrayList 为什么线程不安全

答法：

> 多线程 add 时可能出现 size 更新丢失、数组越界、元素覆盖等问题。需要用 Collections.synchronizedList、CopyOnWriteArrayList 或外部加锁。

### 8.4 CopyOnWriteArrayList 适合什么场景

答法：

> 适合读多写少、数据量不大的场景，比如配置、白名单、监听器列表。写频繁时不适合，因为每次写都复制数组。

### 8.5 fail-fast 是什么

答法：

> fail-fast 是集合遍历时检测结构性修改的机制，发现 modCount 和 expectedModCount 不一致就抛 ConcurrentModificationException。它不是线程安全保证，只是快速失败机制。
